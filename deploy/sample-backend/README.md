# Isolated `/sample-api` deployment

This directory packages a second enterprise platform without sharing the existing `/enterprise` runtime. The Compose project, SQL Server database, Redis, MinIO, JWT secret, RSA keys, credentials, install ID, ports, network, and volumes are independent.

## Fixed boundaries

- Existing `/enterprise` and `/enterprise/prod-api/` routes are never edited by these scripts.
- New UI: `https://www.fengxingzhicheng.com/sample/`
- New backend proxy: `https://www.fengxingzhicheng.com/sample-api/`
- New object proxy: `https://www.fengxingzhicheng.com/sample-oss/`
- Host-only ports: backend `18012`, SQL Server `21434`, Redis `26380`, MinIO `19000/19001`.
- Database: `sample_fengxing`; application login: `sample_app`.
- Compose project: `fx-sample-backend`; no fixed container names are used.
- Backend and UI source commits are pinned in `versions.env` and in the deployment workflow.

The browser runtime file intentionally exposes only the request-encryption public key and response-decryption private key required by the upstream protocol. The backend request-decryption private key remains host-only.

Anonymous object responses carry a restrictive CSP sandbox, `nosniff`, and no-referrer policy at Nginx. This keeps uploaded HTML or SVG from executing with the primary site's origin while preserving image and document embedding. The Docker build context is allowlisted to `Dockerfile` and `backend.jar`, so `.env` and the signed license never enter an image build.

## One-time host preparation

Use an `x86_64` host and install Docker Compose v2, OpenSSL, Apache `htpasswd`, Node.js 20 or newer, Nginx, and curl. Then create the unique deployment identity and credentials:

```bash
sudo env ENTERPRISE_VENDOR_OPEN_BASE_URL=https://REAL-VENDOR-ORIGIN \
  /path/to/generate-env.sh
```

`generate-env.sh` writes only `/opt/fx-sample-backend/.env`, with mode `0600`, and refuses to overwrite it. Its install ID is stable across container replacement. Request a vendor-signed license for that exact install ID and install it without changing its contents:

```bash
sudo install -d -m 0700 /opt/fx-sample-backend/license
sudo install -m 0600 sample.lic /opt/fx-sample-backend/license/sample.lic
```

A placeholder vendor URL or missing/unsigned license is a hard deployment failure before database bootstrap or UI activation. A valid license cannot be generated by this repository.

## Release behavior

GitHub Actions uses commit-pinned actions and external source repositories, verifies both checked-out source commits against `versions.env`, applies both patches with `git apply --check`, removes the upstream UI's build-time RSA variables by name, runs the focused backend install-ID test and UI unit tests, builds the backend with the `prod` Maven profile, and builds the UI for `/sample-api`. Runtime images, including SQL Server, are digest-pinned. The release contains no real secret or license.

On the server, `deploy.sh`:

1. Records current service/container/log state and verifies `/enterprise/prod-api/`.
2. Checks architecture, Node version, resources, port ownership, pinned image pullability, `.env`, HTTPS vendor URL, and signed-license presence.
3. Builds a uniquely tagged candidate backend with an allowlisted Docker context. Existing dependency containers must already match the reviewed image digests.
4. Bootstraps a missing `sample_fengxing` database and requires `sample_schema_verification_ok`; an existing database is verified without replaying the fresh-only baseline.
5. Transactionally creates or rotates the isolated database login, configures MinIO as anonymous-download-only, and requires `sample_runtime_configuration_ok`.
6. Replaces the backend with the candidate, performs encrypted captcha login, calls authenticated user info, imports the signed license, requires vendor gate `ALLOW`, and rejects the workbench vendor-fallback notice. A failed existing-install validation restores the prior backend image.
7. Only after backend validation passes, stages the UI and atomically replaces the managed Nginx `/sample`, `/sample-api`, and `/sample-oss` block while leaving the prior canonical image tag and existing release metadata untouched. UI archives containing traversal paths, links, or special files are rejected before extraction, then all public routes are checked against the candidate.
8. Moves the prior release metadata into a transient rollback directory, installs the new metadata, promotes and recreates the backend under the canonical image tag, then repeats all public checks. Both passes verify the isolated UI marker, runtime configuration, API payload, unchanged `/enterprise/prod-api/`, and exact CSP, `nosniff`, and no-referrer headers on `/sample-oss/`.

If either validation pass fails, the previous `/sample` UI, Nginx file, canonical image tag, release metadata (including SQL/runtime SQL), and backend container are restored in that order. Temporary tags and UI/release rollback directories are removed immediately; no retained backup or duplicate service is created. Any failed first installation stops its candidate Compose services, including failures before database creation; a database created by that failed run is dropped so the fresh-only bootstrap remains retryable.

## Local validation

Use generated throwaway values outside the repository, then run:

```bash
bash -n generate-env.sh deploy.sh
node --check smoke.mjs
docker compose --env-file /path/to/throwaway.env -f compose.yml config --quiet
git -C /path/to/pinned/backend apply --check patches/backend-stable-install-id.patch
git -C /path/to/pinned/ui apply --check patches/ui-runtime-rsa.patch
```

Never copy `.env.example` into production, commit `/opt/fx-sample-backend/.env`, or store `sample.lic` in this repository.
